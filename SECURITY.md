# Politique de sécurité

## Versions prises en charge

Le projet est en développement initial. Seule la dernière version de la branche `main` reçoit des correctifs de sécurité.

## Signaler une vulnérabilité

Ne publiez pas de vulnérabilité, de secret ou de document confidentiel dans une issue publique.

Utilisez de préférence **Security → Report a vulnerability** dans le dépôt GitHub. Si cette option n'est pas disponible, contactez le mainteneur à partir de son profil GitHub sans divulguer publiquement les détails techniques.

Incluez, lorsque possible :

- la version ou le commit concerné;
- les étapes de reproduction;
- l'impact potentiel;
- une proposition de correction;
- la confirmation qu'aucune donnée réelle n'a été exposée.

## Périmètre sensible

Les signalements concernant l'exposition réseau, l'injection de contenu documentaire, les dépendances, la fuite de fichiers, les réponses non fondées ou le contournement des avertissements de sécurité sont particulièrement importants.
